# ESP32-C6 + BNO085 + IM315TRX ファームウェア README

## 1. 目的

この README は、以下のシステム向けArduinoファームウェアをCodexで生成する際の引き継ぎ資料です。

**目標:** Seeed Studio XIAO ESP32-C6を使用してBNO085 IMUから姿勢データ（クォータニオン）を読み取り、最新のクォータニオンをUART経由でIM315TRX無線モジュールへ送信します。

システムのデータフロー:

```text
BNO085
  |
  | I2C
  v
XIAO ESP32-C6
  |
  | UART
  v
IM315TRX
  |
  | 315 MHz無線
  v
受信側 IM315TRX -> 中継マイコン -> 送信側 IM920 -> 920 MHz無線 -> 受信側 IM920 -> PC
```

ファームウェアでは、IMUからのデータ取得と無線送信を論理的に分離してください。

---

## 2. ハードウェア

- MCU: Seeed Studio XIAO ESP32-C6
- IMU: BNO085ブレークアウトボード
- 無線モジュール: IM315TRX
- 開発環境: Arduino IDE / Arduinoフレームワーク
- PCデバッグ用シリアル: XIAO ESP32-C6のUSBシリアル

---

## 3. XIAO ESP32-C6のピン割り当て

プロジェクトのデフォルトとして、次の割り当てを使用します。

| XIAOピン | ESP32-C6 GPIO | このプロジェクトでの機能 |
|---|---:|---|
| D1 | GPIO1 | 未使用（IM315TRX BUSYは接続しない） |
| D2 | GPIO2 | 未使用（IM315TRX RESETは接続しない） |
| D4 | GPIO22 | BNO085 SDA |
| D5 | GPIO23 | BNO085 SCL |
| D6 | GPIO16 | UART TX -> IM315TRX RxD |
| D7 | GPIO17 | UART RX <- IM315TRX TxD |
| 3V3 | - | BNO085 / IM315TRX電源 |
| GND | - | 共通GND |

重要事項:

- D4/D5はI2Cに使用します。
- D6/D7はUARTに使用します。
- IM315TRXのBUSY・RESETはESP32に接続せず、ファームウェアはBUSYの状態にかかわらず常に送受信します。
- 配線を変更しない限り、D4、D5、D6、D7を無関係な機能に再利用しないでください。

推奨するファームウェア定数:

```cpp
constexpr int PIN_I2C_SDA = D4;
constexpr int PIN_I2C_SCL = D5;

constexpr int PIN_IM315_TX = D6;  // ESP32 TX -> IM315TRX RxD
constexpr int PIN_IM315_RX = D7;  // ESP32 RX <- IM315TRX TxD
```

## 4. BNO085 <-> ESP32-C6の配線

I2Cを使用します。

| BNO085 | XIAO ESP32-C6 | 用途 |
|---|---|---|
| VIN | 3V3 | 電源 |
| GND | GND | GND |
| SDA | D4 / GPIO22 | I2Cデータ |
| SCL | D5 / GPIO23 | I2Cクロック |

配線:

```text
BNO085                  XIAO ESP32-C6
--------------------------------------
VIN   ----------------  3V3
GND   ----------------  GND
SDA   ----------------  D4 / GPIO22
SCL   ----------------  D5 / GPIO23
```

現在の設計では、初期実装時にBNO085のINTおよびRSTは必要ありません。

既存プロジェクトでは、次のようなBNO085のクォータニオンレポートを使用します。

- `SH2_ROTATION_VECTOR`
- または `SH2_GAME_ROTATION_VECTOR`

Codexは、実際のプロジェクトコードで選択されているレポートタイプを、無断で変更せず維持してください。

クォータニオンの各成分は、次の順序で明示的に扱ってください。

```text
w, x, y, z
```

ライブラリやAPIによっては、クォータニオンが内部的に次の順序で表現されることがあるため注意してください。

```text
x, y, z, w
```

変換内容を文書化せずに成分の順序を変更しないでください。

## 5. IM315TRXのピン番号

IM315TRXで使用する主な物理ピン:

| IM315TRX信号 | ピン番号 | 用途 |
|---|---:|---|
| BUSY | 1 | モジュールのビジー状態 |
| RxD | 6 | IM315TRXへのUART入力 |
| TxD | 7 | IM315TRXからのUART出力 |
| MODE1 | 17 | 動作モード選択 |
| MODE2 | 18 | 動作モード選択 |
| MODE3 | 19 | 動作モード選択 |
| REG | 22 | ID登録モード入力 |
| VCC | 23 | 2.0～3.6 V電源 |
| GND | 24 | GND |
| RESET | 25 | リセット入出力 |
| NC | 26 | 未接続にする |

## 6. IM315TRX <-> ESP32-C6の配線

このプロジェクトで推奨する配線:

| IM315TRX | ピン | XIAO ESP32-C6 | 備考 |
|---|---:|---|---|
| VCC | 23 | 3V3 | 5 Vには接続しないこと |
| GND | 24 | GND | 共通GND |
| RxD | 6 | D6 / GPIO16 / TX | UARTは交差接続 |
| TxD | 7 | D7 / GPIO17 / RX | UARTは交差接続 |
| BUSY | 1 | オープン | ESP32には接続しない |
| RESET | 25 | オープン | ESP32には接続しない |
| MODE1 | 17 | オープン | 内部プルアップ -> HIGH |
| MODE2 | 18 | GND | LOW |
| MODE3 | 19 | GND | LOW |
| REG | 22 | オープン | 内部プルアップ -> HIGH |
| NC | 26 | オープン | 必ず未接続にする |

UART配線:

```text
XIAO ESP32-C6                  IM315TRX
-----------------------------------------
D6 / TX  ------------------>   pin 6 RxD
D7 / RX  <------------------   pin 7 TxD
```

TXとRXは交差接続する必要があります。

## 7. IM315TRXの動作モード

使用するモードは**データモード（Data Mode）**です。

モード選択は次のとおりです。

```text
MODE1 = HIGH
MODE2 = LOW
MODE3 = LOW
REG   = HIGH
```

現在のハードウェア構成:

```text
MODE1 -> オープン  （内部プルアップ -> HIGH）
MODE2 -> GND       （LOW）
MODE3 -> GND       （LOW）
REG   -> オープン  （内部プルアップ -> HIGH）
```

したがって、現在の固定モード設計では、CodexがソフトウェアからMODE1/MODE2/MODE3/REGを制御する必要はありません。

後からハードウェアを変更しない限り、これらのピンにESP32のGPIOを割り当てないでください。

### はんだブリッジに注意

MODE1（17番）、MODE2（18番）、MODE3（19番）は近接しています。実機で17番と19番のピンヘッダがはんだでつながり、MODE1がLOWに引かれてデータモードで起動しない不具合がありました。この状態では、UARTで応答があっても無線の送受信ができません。

はんだ付けの後は、電源を入れる前にテスターで次を確認してください。

- 隣り合うピン同士、特に17～19番と22～26番の間に導通がないこと
- 18番と19番以外のピンがGNDと導通していないこと
- 通電時にMODE1とREGがHIGH、MODE2とMODE3がLOWであること

## 8. BUSY・RESETの扱い

このプロジェクトでは、IM315TRXのBUSY（1番ピン）とRESET（25番ピン）を**ESP32に接続しません**。どちらもオープンにします。

ファームウェアのルール:

```text
BUSYの状態は確認しない
送信間隔ごとに常にUARTへ送信する
UART受信は常に処理する
前回コマンドの応答（OK/NG）が届いていなくても次の送信を行う
```

注意事項:

- IM315TRXはBUSYがHIGHの間に受け取ったデータやコマンドを無視する場合があります。BUSYを確認しないため、一部の送信が失われる可能性があります。
- 送信が失われても、次の送信間隔で最新のクォータニオンが送られます。
- 応答が届かなかったコマンドは`ERROR:IM315_REPLY_TIMEOUT`として報告します。
- RESETはモジュール内部でプルアップされている前提でオープンにします。ESP32から外部リセットは行いません。

## 10. I2Cの設定

BNO085では次のピンを使用します。

```text
SDA = D4 / GPIO22
SCL = D5 / GPIO23
```

一般的な初期化:

```cpp
Wire.begin(PIN_I2C_SDA, PIN_I2C_SCL);
```

BNO085ライブラリが独自に`Wire`を初期化する場合は、同じバスを競合する方法で初期化しないでください。

プロジェクトに既存のBNO085ライブラリがある場合、Codexはそのライブラリを使用してください。

現在のプロジェクトですでにI2Cアドレスやライブラリが指定されている場合、別のものを推測して使用しないでください。

---

## 11. UARTの設定

IM315TRXのUARTでは次のピンを使用します。

```text
ESP32 TX = D6 / GPIO16 -> IM315TRX RxD（6番ピン）
ESP32 RX = D7 / GPIO17 <- IM315TRX TxD（7番ピン）
```

SoftwareSerialではなく、ハードウェアUARTを使用してください。

概念的なコード:

```cpp
HardwareSerial radioSerial(...);
radioSerial.begin(IM315_BAUD, SERIAL_8N1, PIN_IM315_RX, PIN_IM315_TX);
```

### 重要: ボーレート

USBデバッグシリアルの設定からIM315TRXのボーレートを推測しないでください。

たとえば、次のコードはPC/USBデバッグシリアルの通信速度のみを定義します。

```cpp
Serial.begin(115200);
```

`IM315_BAUD`は実際のIM315TRXのシリアル設定と一致させる必要があります。値をハードコードする前に、モジュールの設定またはソフトウェアマニュアルで確認してください。

## 12. 推奨するファームウェア構成

1つの大きなブロッキング処理を`loop()`に記述することは避けてください。

推奨構成:

```text
setup()
 |
 +-- USBデバッグシリアルを初期化
 +-- I2Cを初期化
 +-- BNO085を初期化
 +-- IM315 UARTを初期化
 |
 v
loop()
 |
 +-- BNO085をポーリング／読み取り
 |     |
 |     +-- 新しいクォータニオンがある場合:
 |           最新のクォータニオンを保存
 |
 +-- 無線送信間隔を確認
       |
       +-- 間隔が経過していれば、BUSYに関係なく最新のクォータニオンを送信
```

BNO085の測定レートとIM315TRXの送信レートを同じにする必要はありません。

初期構成の例:

```text
BNO085データ取得: 約50 Hz
無線送信:         より低い設定可能なレート（初期値の例: 10 Hz）
```

正確な無線送信レートは、IM315TRXのスループットおよびパケット／コマンド要件をテストした後で調整してください。

最新の有効なクォータニオンを保存し、送信間隔ごとに最新サンプルを送信してください。

---

## 13. 推奨するデータ構造

最新のIMUサンプルには、小さな構造体を使用します。

例:

```cpp
struct QuaternionSample {
    float w;
    float x;
    float y;
    float z;
    uint32_t timestamp_ms;
    bool valid;
};
```

これにより、センサーデータの取得と無線送信用の整形を分離できます。

## 14. 推奨する無線ペイロード

初期デバッグでは、人が読める1行形式が便利です。

```text
Q,w,x,y,z
```

例:

```text
Q,0.999998,0.000056,0.000090,0.002016
```

各メッセージは、`\n`など一貫した文字で終端してください。

通信が安定して動作するようになった後、通信量の削減やより強固なフレーミングが必要であれば、バイナリパケットを検討できます。

PC側の受信プログラム／パーサーも同時に更新しない限り、ペイロード形式を変更しないでください。

## 15. タイミング要件

`millis()`またはノンブロッキングなスケジューラを使用してください。

メインのデータ取得処理内では、次のようなコードを避けてください。

```cpp
delay(100);
```

このようなコードは、IMUデータを適切なタイミングで処理できなくなる原因になります。

代わりに、次のような処理を使用してください。

```cpp
if (millis() - lastSendMs >= SEND_INTERVAL_MS) {
    // 送信を試行
}
```

## 16. エラー処理

Codexが生成するファームウェアでは、少なくとも次の状態を検出／報告してください。

1. BNO085の初期化失敗。
2. 異常に長い期間、BNO085から新しいデータを受信していない。
3. クォータニオンの値が無効、または有限値ではない。
4. IM315TRXから送信コマンドへの応答が届かない。
5. 応答を解析する場合のUARTエラー／不正な形式の応答。

デバッグ出力にはUSBの`Serial`を使用してください。

ループの反復ごとにデバッグシリアルへ大量出力しないでください。

## 17. クォータニオンの検証

送信前に次の項目を確認してください。

```text
- 4つの成分がすべて有限値であることを確認する
- 必要に応じてクォータニオンのノルムを計算する
- 明らかに無効なサンプルを破棄する
```

クォータニオンのノルム:

```text
norm = sqrt(w*w + x*x + y*y + z*z)
```

正規化されたクォータニオンでは、ノルムが1に近い値になります。

ライブラリが正規化された出力を保証している場合、明確な理由なく再度正規化しないでください。

## 20. 電気的な注意事項

### IM315TRXの電源

IM315TRXのVCC仕様:

```text
2.0 V～3.6 V
```

XIAO ESP32-C6の**3V3**電源を使用してください。

IM315TRXのVCCを5 Vに接続しないでください。

### 共通GND

次のGNDは共通の基準電位に接続する必要があります。

```text
XIAO ESP32-C6 GND
BNO085 GND
IM315TRX GND
```

### IM315TRXのNC

```text
26番ピン NC -> オープン
```

何も接続しないでください。

## 21. 配線の最終まとめ

```text
                    XIAO ESP32-C6
                   +---------------+
BNO085 SDA --------| D4 / GPIO22   |
BNO085 SCL --------| D5 / GPIO23   |
                   |               |
IM315TRX RxD <-----| D6 / GPIO16 TX|
IM315TRX TxD ----->| D7 / GPIO17 RX|
                   |               |
BNO085 VIN --------| 3V3           |
IM315TRX VCC ------| 3V3           |
BNO085 GND --------| GND           |
IM315TRX GND ------| GND           |
                   +---------------+

IM315TRX:
MODE1 17番ピン -> オープン -> HIGH
MODE2 18番ピン -> GND      -> LOW
MODE3 19番ピン -> GND      -> LOW
REG   22番ピン -> オープン -> HIGH
NC    26番ピン -> オープン

RESET 25番ピン -> オープン（ESP32に接続しない）
```

これにより、IM315TRXのデータモードが選択されます。

```text
MODE1 MODE2 MODE3
  H     L     L
```

## 22. Codexによる実装の主な目標

次の機能を持つファームウェアを生成します。

1. XIAO ESP32-C6を初期化する。
2. D4/D5のI2Cを介してBNO085を初期化する。
3. クォータニオンの測定値を受信する。
4. 最新の有効なクォータニオンを保存する。
5. D6/D7でIM315TRX用のハードウェアUARTを初期化する。
6. BUSY・RESETは使用せず、BUSYの状態にかかわらず常に送受信する。
7. 設定可能な間隔で最新のクォータニオンを送信する。
8. USBシリアルへ有用な診断情報を出力する。
9. ハードウェア依存の設定をソース先頭の定数にまとめる。
10. 長時間のブロッキング遅延を避ける。

## 23. ピン確認に使用した資料

- Seeed Studio XIAO ESP32-C6のピンマップ:
  - D4 = SDA / GPIO22
  - D5 = SCL / GPIO23
  - D6 = TX / GPIO16
  - D7 = RX / GPIO17
  - D1 = GPIO1
  - D2 = GPIO2
- IM315TRXハードウェアマニュアル:
  - BUSY = 1番ピン
  - RxD = 6番ピン
  - TxD = 7番ピン
  - MODE1/2/3 = 17/18/19番ピン
  - REG = 22番ピン
  - VCC = 23番ピン
  - GND = 24番ピン
  - RESET = 25番ピン
  - NC = 26番ピン
  - データモード = MODE1 H、MODE2 L、MODE3 L
  - REGをLOWにするとID登録モードになる
  - BUSYがLOWのとき、コマンド／データを受け付ける
  - RESETは入出力端子

## 24. プログラムの実行手順

この節では、`BNO085_NoMag_IM315TRX/BNO085_NoMag_IM315TRX.ino`をXIAO ESP32-C6へ書き込み、USBシリアルで動作を確認し、`python/BNO085_NoMag.py`で姿勢を可視化するまでの手順を説明します。

### 24.1. このプログラムで使用する配線

BNO085はI2Cで接続します。SDAにはD4、SCLにはD5を使用し、IM315TRX用のD6、D7と競合しない構成です。

#### BNO085（I2C接続）

| BNO085 | XIAO ESP32-C6 |
|---|---|
| SDA | D4 / GPIO22 |
| SCL | D5 / GPIO23 |
| VIN | 3V3 |
| GND | GND |

現在の設計では、BNO085のINT、RST、CSは接続しません。

#### IM315TRX

| IM315TRX | ピン番号 | XIAO ESP32-C6 |
|---|---:|---|
| BUSY | 1 | オープン |
| RxD | 6 | D6 / TX |
| TxD | 7 | D7 / RX |
| MODE1 | 17 | オープン |
| MODE2 | 18 | GND |
| MODE3 | 19 | GND |
| REG | 22 | オープン |
| VCC | 23 | 3V3 |
| GND | 24 | GND |
| RESET | 25 | オープン |
| NC | 26 | オープン |

すべての機器のGNDを共通にしてください。IM315TRXのVCCには5 Vを接続しないでください。

### 24.2. Arduino IDEの準備

1. Arduino IDEを起動します。
2. ボードマネージャーからESP32用ボードパッケージをインストールします。
3. ボードとして`XIAO_ESP32C6`を選択します。
4. ライブラリマネージャーから`Adafruit BNO08x`をインストールします。
5. XIAO ESP32-C6をUSBケーブルでPCへ接続します。
6. Arduino IDEの「ツール」から、XIAO ESP32-C6に対応するCOMポートを選択します。

### 24.3. IM315TRXの通信設定を確認する

プログラムの初期値は次のとおりです。

```cpp
constexpr uint32_t IM315_BAUD = 19200;
```

IM315TRXのUART設定が19200 bps、8データビット、パリティなし、1ストップビットであることを確認してください。実機の設定が異なる場合は、`BNO085_NoMag_IM315TRX.ino`の`IM315_BAUD`を変更します。

無線送信には次のコマンド形式を使用しています。

```text
TXDT <16文字のクォータニオンデータ>\r\n
```

使用しているIM315TRXの設定・ファームウェアで`TXDT`コマンドが利用できることも確認してください。

実機確認結果: IM315TRX Ver.01.07で、19200 bps（8N1）での通信と`TXDT`による送信を確認済みです。

### 24.4. XIAO ESP32-C6へ書き込む

1. Arduino IDEで`BNO085_NoMag_IM315TRX/BNO085_NoMag_IM315TRX.ino`を開きます。
2. 「検証」を実行し、コンパイルエラーがないことを確認します。
3. 「書き込み」を実行します。
4. 書き込み完了後、シリアルモニタを115200 bpsで開きます。
5. 必要であれば、XIAO ESP32-C6のRESETボタンを押します。

正常に起動すると、次のような出力が表示されます。

```text
READY
Q,0.999998,0.000056,0.000090,0.002016
TX:4000000100010021
IM315:OK
```

各行の意味:

| 出力 | 意味 |
|---|---|
| `READY` | BNO085の初期化とレポート開始に成功 |
| `Q,w,x,y,z` | Python可視化用のクォータニオン |
| `TX:...` | IM315TRXへ送信した16進数ペイロード |
| `IM315:OK` | IM315TRXが送信コマンドを受理 |
| `IM315:NG` | IM315TRXが送信コマンドを拒否 |

### 24.8. 地上側で無線受信を確認する

地上側の最終構成では、315 MHzで受信したデータを920 MHzでPC側へ再送します。全体の経路は次のとおりです。

```text
受信側 IM315TRX
  -> UART
中継マイコン
  -> UART（TXDTコマンド）
送信側 IM920
  -> 920 MHz無線
受信側 IM920
  -> USB-UART
PC
```

中継を組む前に、受信側IM315TRXをUSBインターフェイスボード IM920-USB2 経由でPCに直接つなぎ、315 MHz区間だけを確認します。IM315TRXにはプログラムを書き込みません。PCのターミナルソフト（Tera Term）からコマンドを送って設定し、受信データを画面で確認します。

以下の手順は、2026年10月に送信側・受信側とも IM315TRX Ver.01.07 で動作を確認したものです。

#### 24.8.1. 受信側IM315TRXをPCに接続する

1. 受信側IM315TRXをIM920-USB2に載せ、USBケーブルでPCに接続します。
2. デバイスマネージャーの「ポート（COMとLPT）」に、CP2102NのCOMポートが表示されることを確認します。表示されない場合は、Silicon LabsのCP210xドライバをインストールします。
3. 受信側もデータモード（MODE1 H、MODE2 L、MODE3 L、REG H）で動作している必要があります。IM920-USB2上でのMODE端子の扱いは、IM920-USB2の取扱説明書（回路図）で確認してください。

#### 24.8.2. Tera Termを設定する

「新しい接続」で「シリアル」を選び、手順24.8.1のCOMポートを指定します。「設定」→「シリアルポート」を次のように設定します。

```text
スピード:   19200
データ:     8 bit
パリティ:   none
ストップ:   1 bit
フロー制御: none
送信遅延:   10 ミリ秒/字、100 ミリ秒/行
```

「設定」→「端末」で、改行コードの送信を「CR+LF」にし、「ローカルエコー」にチェックを入れます。

入力時の注意:

- Tera Termは打った文字を1文字ずつ送信します。打ち間違えたときはBackspaceで直さず、Enterを押してから打ち直してください。崩れた文字列は`NG`になります。
- 1行ずつ入力し、応答を確認してから次の行に進んでください。不揮発メモリへの書込み中はBUSYがHIGHになり、その間に届いた文字は無視されます。

#### 24.8.3. 動作確認コマンド

送信側・受信側それぞれのIM315TRXで、次のコマンドを1行ずつ実行します。送信側のIDは、受信側への登録に使うので控えておきます。

| コマンド | 内容 | 応答例 |
|---|---|---|
| `RDID` | 固有IDの読出し | `A51F` |
| `RDVR` | 製品バージョンの読出し | `IM315TRx Ver.01.07` |
| `RDCH` | 無線チャンネルの読出し | `20` |

`RDCH`は、IMコマンド一覧表 Ver.3.0ではIM315TRX対応とされています。ただし、実機（Ver.01.07）で`NG`が返った例があります。その場合は、送信側・受信側の両方で次を実行し、チャンネルを出荷時の値の20にそろえます。

```text
ENWR
STCH 20
DSWR
```

#### 24.8.4. 送信側のIDを受信側に登録する

受信側IM315TRXは、登録された送信モジュールのデータだけを出力します。受信側で次を1行ずつ実行します。`A51F`は送信側の`RDID`の値に置き換えてください。

```text
ENWR
SRID A51F
RRID
DSWR
```

| 送った行 | 正常な応答 | 異常時の意味 |
|---|---|---|
| `ENWR` | `OK` | 応答がなければコマンドが届いていない |
| `SRID A51F` | `OK` | `NG`なら書込み許可が有効になっていない |
| `RRID` | `A51F` | 空行なら登録されていない |
| `DSWR` | `OK` | - |

`ENWR`による書込み許可は、電源を切るかUSBを抜き差しすると無効に戻ります。`SRID`の直前に、同じ接続のまま`ENWR`を送ってください。登録したIDは電源を切っても保持されます。

#### 24.8.5. 受信データを確認する

送信側のXIAO ESP32-C6で`BNO085_NoMag_IM315TRX/BNO085_NoMag_IM315TRX.ino`を動作させると、受信側のTera Termに次のような行が約10 Hzで表示されます（実機の出力例）。

```text
00,A51F,C9:36,9E,01,DD,FC,5F,21,1C
00,A51F,CA:36,9E,01,E6,FC,5E,21,1B
00,A51F,CC:36,9F,01,EE,FC,5F,21,1A
00,A51F,CA:36,A1,01,F3,FC,5C,21,15
```

受信行の形式（IM315シリーズ取扱説明書 ソフトウェア編 7-2項）:

```text
aa,bbbb,cc:d1,d2,d3,d4,d5,d6,d7,d8<CR><LF>
```

| 部分 | 意味 |
|---|---|
| `aa` | 送信側のノード番号（16進2桁） |
| `bbbb` | 送信側の固有ID（16進4桁） |
| `cc` | 受信信号強度 RSSI（16進2桁） |
| `d1`～`d8` | ユーザデータ8バイト。1バイトずつカンマ区切りの16進2桁 |

送信側が`TXDT`で送る16文字の連続した16進数とは形式が異なります。中継マイコンやPC側のパーサーでは、コロンの後ろを取り出してカンマを除くと、送信側の16文字のペイロードと同じ形になります。

#### 24.8.6. ペイロードをクォータニオンに戻す

ユーザデータ8バイトは次の順序です。

```text
w上位, w下位, x上位, x下位, y上位, y下位, z上位, z下位
```

各成分はビッグエンディアンの符号付き16ビットQ14値です。符号付き16ビット整数として解釈して16384.0で割ります。

```text
quaternion_component = signed_q14_value / 16384.0
```

上の出力例1行目の変換結果:

| 成分 | 16進 | 符号付き整数 | 実数 |
|---|---|---:|---:|
| w | `369E` | 13982 | 0.8534 |
| x | `01DD` | 477 | 0.0291 |
| y | `FC5F` | -929 | -0.0567 |
| z | `211C` | 8476 | 0.5173 |

ノルムは約1.000になり、正しく受信できていることを確認できます。

#### 24.8.7. 920 MHz中継を組む

315 MHz区間の確認後、最終構成の中継を組みます。

IM315TRXとIM920は形状・ピン配置や一部のIMコマンドに互換性がありますが、315 MHzと920 MHzの無線を相互に直接中継する機能はありません。そのため、受信側IM315TRXのUART出力を解析し、IM920の送信コマンドへ変換する中継マイコン用プログラムが必要です。通常、IM920本体へ独自プログラムを書き込む必要はなく、UARTからコマンドで制御します。

1. 受信側IM315TRXと送信側IM920を、中継マイコンの別々のUARTへ接続します。
2. 中継マイコンでIM315TRXの受信行（24.8.5の形式）を解析し、コロン以降からカンマを除いた16文字を取り出します。
3. 取り出したペイロードを、IM920へ`TXDT <payload>\r\n`として送ります。
4. 送信側と受信側のIM920について、チャンネルなど必要な無線設定を一致させます。受信側IM920にも、24.8.4と同じ手順で送信側IM920の固有IDを登録します。
5. 受信側IM920をIM920-USB2などの3.3 V対応USB-UART変換器でPCへ接続します。
6. PCで、24.8.5と同じ形式の受信行が連続して更新されることを確認します。

PC側の姿勢表示には、`python/BNO085_NoMag.py`を受信行の形式に合わせて改修する必要があります。現在のスクリプトは、XIAO ESP32-C6のUSBシリアルから`Q,w,x,y,z`形式の行を読む作りです。

### 24.9. 主なエラー表示と確認項目

| エラー表示 | 確認項目 |
|---|---|
| `ERROR:BNO085_NOT_FOUND` | I2C配線（SDA/SCL）、電源、I2Cアドレスを確認 |
| `ERROR:REPORT_START_FAILED` | BNO085との通信とライブラリを確認 |
| `ERROR:INVALID_QUATERNION` | BNO085の接続状態とセンサーデータを確認 |
| `ERROR:IM315_TX_REJECTED` | IM315TRXのモード、登録状態、コマンド形式を確認 |
| `ERROR:IM315_REPLY_TIMEOUT` | ボーレート、TX/RX交差配線、モジュール電源を確認。BUSY中に送ったコマンドが無視された場合にも表示される |
| 応答はあるが送受信できない | MODE1～MODE3、REGのピン間にはんだブリッジがないか確認（7節） |
| Tera Termで`RDCH`が`NG` | 打ち直しても`NG`なら、`ENWR`→`STCH 20`→`DSWR`でチャンネルを20にそろえる（24.8.3） |
| Tera Termで`RRID`が空行 | 受信IDが未登録。1行ずつ応答を確認しながら`ENWR`→`SRID`をやり直す（24.8.4） |
| 受信側に何も表示されない | 送信側IDの登録、チャンネルの一致、送信側の`IM315:OK`表示を確認 |
